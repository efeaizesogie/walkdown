Walkdown

A mock auditor for medical-device software teams, inside Jira. Walkdown samples requirements the way an auditor would, walks each trace from design to code, verification, risk control and release, and stops at the first broken link. It grades gaps as major, minor or observation, with IEC 62304, ISO 14971, ISO 13485 and 21 CFR 820.30 references.

Get started

  1. Install Walkdown in Jira and Confluence.
  2. Open Apps → Walkdown and click Load the GlucoLoop sample. It builds a fictional insulin-dosing project with a few traces broken on purpose.
  3. Click Run rehearsal, then read the auditor's log.
  4. Open a requirement to see its Walkdown trace panel, or ask Walkdown Auditor in Rovo.

Use it on your own project

WhatHow Walkdown recognises it
Requirementlabel wd-requirement
Safety classlabel iec62304-class-a, -b or -c; safety-related; changed-since-release
Verification testlabel wd-test, linked with Verifies; result label result-pass, result-fail or result-not-run
Hazardlabel wd-risk, linked with Risk control (requirement mitigates hazard); control-verified once effectiveness is verified
Designa Confluence page linked to the requirement
Codecommits or pull requests linked to the work item, read through Teamwork Graph and Jira development information
ReleaseFix version

Optional admin steps

  • Release gate: add the Walkdown trace check rule to your workflow's release transition (Workflow editor → transition → Validate details).
  • MCP: in Atlassian Administration → Connected apps → Walkdown, click Enable tools on each installation, then add https://mcp.atlassian.com/forge/b76b5155-9742-4c85-b2ec-10bf789babad to your MCP client.
